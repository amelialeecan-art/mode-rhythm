# MODE 사용자-facing 언어 원칙

한 줄 원칙: **숫자는 엄격하게, 말은 사람처럼.**

사용자가 통계 결과를 "해석"하게 만들지 않는다. 친구가 자기 데이터를 설명해주는
말을 그냥 읽고 이해하게 만든다. 앱을 고칠 때 이 문서를 먼저 읽는다.

이 문서는 **표현층(presentation)** 규칙이다. DB/schema/분석 알고리즘/계산 결과는
바꾸지 않는다(그건 `MODE-V2-DATA-PHILOSOPHY.md`가 고정한다).

---

## 1. 핵심 원칙

- **결과는 먼저 이해되게.** 첫 문장을 보는 순간 "아 나는 이럴 때 이렇게 되는구나"가 돼야 한다.
- **통계 용어는 메인에서 추방, 상세로.** baseline / effect / coverage / association /
  same direction / lag / confidence / cluster / centroid / D-7 같은 표현은 메인 문구에 쓰지 않는다.
  필요하면 "자세히 보기"(2층)에 둔다.
- **관찰 결과는 직설적으로.** "무슨 일이 있었고 그 뒤 무엇이 달랐는지"는 바로 말한다
  (예: "늦게 잔 다음날에는 에너지가 더 낮았어요").
- **원인은 함부로 확정하지 않는다.** "늦게 자서 떨어졌어요" / "생리 때문에" 같은 인과 단정 금지.
  `copy/tone.ts`의 `assertGuard`/`containsAssertion`를 통과해야 한다.
- **예측은 결과처럼 말하지 않는다.** 이미 일어난 일과 앞으로의 추정을 문구에서 구분한다.
- **없는 숫자/비교군을 만들지 않는다.** 엔진이 이미 계산한 값만 문장으로 조합한다.

## 2. 말투

설명·안내·결과·예측·빈 화면·오류 문구는 **반말 친구 말투**로 통일한다(~했어/~였어/~보여/
~볼 수 있어). "내 기록을 다 아는 친구가 '너 이럴 때 이런 식이더라' 하고 알려주는" 느낌.
단 **버튼/조작 문구는 그대로 짧고 명확하게**(기록하기·수정·자세히 보기·완료) — 반말 문장으로
만들지 않는다. 질문 문구도 친구가 묻듯 반말("지금 배가 얼마나 고파?").

통계 보고서를 번역한 느낌으로 두지 않는다. 데이터 의미를 먼저 전달하고, **가벼운 상황에서만**
한마디 얹는다(늦잠·밤샘·화면시간·평범한 식욕 변화 등). 다음에는 농담하지 않는다: 심한 우울·
불안·통증·질병·시술·발열·심각한 기능저하·건강 예외·체중·폭식 결과 자체.

## 3. 숫자 보여주기 (2층 구조)

- **메인** = 이해. 사람말 한 줄 + 가능하면 `평소 → 이때` 실측 비교.
  - "평소에는 4점 정도였는데 이때는 6점 정도였어요." (`friendlyCopy.beforeAfterLine`)
- **자세히 보기** = 검증. 정확한 평균·차이·N·CI·FDR/q·보정·lag·coverage·주기 수 등.

차이 숫자 하나만 던지지 않는다("+2.3" ❌).

## 4. 반복 횟수

내부 "4/4 same direction" → 사용자 "최근 4번 모두 비슷했어요."
내부 "6/8" → "비교한 8번 중 6번이 그랬어요." **"같은 방향"은 메인에서 쓰지 않는다.**
(`friendlyCopy.repetitionPhrase`)

## 5. 생리주기

D-7/D0 같은 표기를 메인에서 해석시키지 않는다. `friendlyCopy.cycleWindowPhrase`:
D-7 → "생리하기 일주일 전쯤", D-3 → "생리하기 3일 전쯤", D0 → "생리 시작일 즈음".
예측은 prospective 자료만 쓴다(미래 실제 periodStart를 예측 문구에 쓰지 않는다).

## 6. 예측 vs 결과

- 이미 일어난 결과: "지난 네 번 생리에서는 일주일 전부터 음식이 더 당겼어요."
- 앞으로의 추정: "이번에도 비슷하다면 이번 주쯤 올라올 수 있어요." (엔진이 지원할 때만)
- 자료 부족: "아직 다음 패턴을 예상할 만큼 기록이 충분하지 않아요." (없는 예측을 만들지 않는다)

## 7. 신뢰도

badge만 던지지 않고 사람말로 설명한다(`friendlyCopy.confidenceWords`):
강함="기록도 충분하고 여러 번 반복돼서 꽤 믿을 만해요", 보통="몇 번 반복됐지만 아직 많지는 않아요",
낮음="아직 참고 정도로만 봐주세요".

## 8. Core 12 표시명

내부 field 이름과 0~10 척도는 **절대 바꾸지 않는다**(`modelsV2.CORE_METRICS`). 화면 표시명·질문만
사람말로 한다. hunger/craving/bingeUrge 셋은 특히 차이가 바로 이해돼야 한다
("배가 진짜 고픈가 / 음식이 당기나 / 멈추기 힘들 것 같나"). 기존 표시명이 더 자연스러우면 그걸 우선한다.

## 9. 기존 문구 보존

repository에 이미 사람이 다듬어 둔 자연스러운 문구(예: `analysisVoice.ts`, `todayVoice.ts`,
`rhythmVoice.ts`의 해요체 표현)는 **우선 보존한다.** 이 작업을 이유로 좋은 문구를
"~경향이 있습니다" 같은 딱딱한 문장으로 되돌리지 않는다. 통계/개발자 언어가 화면으로 새어
나오는 곳만 사람말로 바꾼다.

## 10. 헬퍼 위치

표시 전용 순수 헬퍼는 `src/screens/Analysis/friendlyCopy.ts`,
분석별 문장은 각 `*Voice.ts`(analysisVoice/temporalVoice/todayVoice/rhythmVoice)에 둔다.
모든 문장을 하나의 거대한 generic template으로 만들지 않는다 — 분석 종류마다 자연스러운 문장이 다르다.

## 11. 절대 금지(문장 생성 안전 규칙)

없는 숫자/비교군 만들기 · effect 방향 뒤집기 · 반복 없는데 "항상" · 2회를 "계속 반복" ·
보정 안 했는데 "다른 조건 봐도" · timestamp 순서 없는데 "이후/뒤" · 낮은 신뢰도인데 "확실히" ·
예측을 이미 일어난 사실처럼 · retrospective를 prospective 예측에 몰래 사용 · 농담 위해 데이터 의미 과장.
